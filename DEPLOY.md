# Выкладка сайта

Собранный сайт — статика: HTML, CSS, JS и картинки. Никакого сервера,
базы данных и бэкенда ему не нужно, достаточно любого хостинга статики.

## Собрать

```bash
npm install --prefix .design/hybrid
npm run build --prefix .design/hybrid
```

Готовый сайт появится в `.design/hybrid/dist/` — 292 файла, около 11 МБ.
Именно эту папку и отдают хостингу. Проверить её локально перед выкладкой:

```bash
npx vite preview --prefix .design/hybrid --port 5199
```

Проверено: `/`, `/storyboard.html`, `/storyboard/manifest.json` и
`/favicon.svg` отдаются кодом 200.

`dist/` намеренно НЕ хранится в гите (`.gitignore`): это результат сборки,
он пересобирается одной командой из исходников и, попав в историю, распухал
бы на 12 МБ при каждой правке фотографии.

## Где сайт стоит сейчас

Не на Netlify и не на Vercel: `arisheniaa.ru` отдаёт **Caddy** с обычного
сервера (`194.87.187.207`, заголовок `Via: 1.1 Caddy`). Заголовки
безопасности там выставлены руками и разумно — CSP, HSTS, `X-Frame-Options`,
`Referrer-Policy`, `X-Content-Type-Options`.

**Автоматической связки «пуш в `master` → пересборка сайта» НЕТ.** Проверено
11 августа 2026: после пуша прошло 25 минут, метка `Last-Modified` у всех
файлов сайта не сдвинулась. В репозитории тоже нет ни GitHub Actions, ни
другого CI. Выкладка делается человеком.

Как это проверить в любой момент, не заходя на сервер:

```bash
curl -sI https://arisheniaa.ru/ | grep -i last-modified
```

Метка одна на все файлы сайта и означает время последней выкладки, а не
правки конкретного файла.

## Репозиторий — источник правды, и это нужно удерживать

11 августа 2026 обнаружилось, что сайт **обогнал репозиторий**: на нём жила
работа, которой в гите не было ни в одной ветке — `canonical` и карточки
Open Graph на обеих страницах, `public/og.jpg`, `robots.txt`, `sitemap.xml`.
Значит выкладку собирали из рабочей копии с незакоммиченными правками, и
сборка из чистого клона дала бы сайт БЕДНЕЕ того, что стоит.

Расхождение устранено: всё живое возвращено в репозиторий и сверено
побайтово. Чтобы оно не возникло снова — правьте только в репозитории и
выкладывайте только собранное из него.

Сверка занимает секунду и врать не умеет: имена файлов в `dist/assets/` —
это хеши содержимого. Совпали с теми, что на сайте, — значит код совпал.

```bash
curl -s https://arisheniaa.ru/ | grep -oE 'assets/[A-Za-z]+-[A-Za-z0-9_-]+\.(js|css)'
```

Сравните вывод с `ls .design/hybrid/dist/assets/`. Разошлось — сайт собран
не из того, что лежит в `master`.

## Куда выкладывать

Подойдёт любой из: Netlify, Vercel, Cloudflare Pages, GitHub Pages,
обычный сервер с nginx. Настройки для всех одинаковые:

| параметр | значение |
|---|---|
| команда сборки | `npm run build --prefix .design/hybrid` |
| папка публикации | `.design/hybrid/dist` |
| версия Node | 20 или новее |

Отдельных правил перенаправления не нужно: обе страницы (`index.html` и
`storyboard.html`) — настоящие файлы, а не маршруты одностраничного
приложения.

## ⚠️ Про GitHub Pages отдельно

Сайт ссылается на свои файлы АБСОЛЮТНЫМИ путями — `/services/…`,
`/storyboard/manifest.json`. Это верно, когда сайт лежит в корне домена:

- `arisheniaa.ru` — работает;
- `имя.github.io` (персональный сайт GitHub) — работает;
- `имя.github.io/название-репозитория/` (сайт проекта) — **НЕ работает**:
  браузер пойдёт за картинками в корень `имя.github.io`, а их там нет.
  Страница откроется без единой фотографии.

Если выкладывать на GitHub Pages именно проектом, нужно сначала задать
базовый путь в `.design/hybrid/vite.config.mts`:

```js
export default defineConfig({
  base: '/название-репозитория/',
  // …остальное без изменений
});
```

и пересобрать. На Netlify, Vercel, Cloudflare и своём домене этого не нужно.

## Что попадёт в публичный репозиторий

Если репозиторий делать открытым, вместе с кодом станут видны:

- все фотографии сайта и весь архив кадров раскадровки (254 снимка);
- цены, контакты и весь текст;
- **локальные пути к вашему архиву на компьютере** — в 18 файлах, включая
  `.design/storyboard-manifest.json`, лежат строки вида
  `C:\Users\Аришения\OneDrive\Рабочий стол\исходники\…`. Это раскрывает имя
  пользователя вашего компьютера и устройство ваших папок. Сами
  фотографии по этим путям недоступны, но информация лишняя.

Первые два пункта — это и есть содержимое сайта, они и так будут публичны.
Третий — нет: он нужен только для пересборки архива на вашей машине.

Убрать его можно, добавив в `.gitignore` строку
`.design/storyboard-manifest.json` и удалив файл из индекса:

```bash
git rm --cached .design/storyboard-manifest.json
```

Сайт от этого не сломается: собранный манифест
(`.design/hybrid/public/storyboard/manifest.json`, тот, что уходит в
браузер) локальных путей не содержит вовсе — проверено. Пересобрать
исходный манифест можно в любой момент:

```bash
node .design/scripts/storyboard-manifest.mjs
```

Но учтите: пересборка требует папку `исходники` на диске, поэтому на чужой
машине из чистого клона архив раскадровки заново не собрать. Готовые
превью в `public/storyboard/` в репозитории есть, и сайту их достаточно.
