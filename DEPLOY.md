# Выкладка сайта

Собранный сайт — статика: HTML, CSS, JS и картинки. Никакого сервера,
базы данных и бэкенда ему не нужно, достаточно любого хостинга статики.

## Собрать

```bash
npm install --prefix .design/hybrid
npm run build --prefix .design/hybrid
```

Готовый сайт появится в `.design/hybrid/dist/` — 292 файла, около 11 МБ.
Именно эту папку и отдают хостингу. Проверить её локально перед выкладкой:

```bash
npx vite preview --prefix .design/hybrid --port 5199
```

Проверено: `/`, `/storyboard.html`, `/storyboard/manifest.json` и
`/favicon.svg` отдаются кодом 200.

`dist/` намеренно НЕ хранится в гите (`.gitignore`): это результат сборки,
он пересобирается одной командой из исходников и, попав в историю, распухал
бы на 12 МБ при каждой правке фотографии.

## Где сайт стоит сейчас

Не на Netlify и не на Vercel: свой сервер в Timeweb Cloud
(`194.87.187.207`). Сайт отдаёт **Caddy** в контейнере, слушая `:8080`
обычным HTTP — TLS терминируется на edge-прокси перед ним. Заголовки
безопасности и правила кеширования заданы в `/opt/arisheniaa-site/Caddyfile`
и написаны с толком: CSP с `blob:` ради выгрузки PDF на второй странице,
вечный кеш ассетам с хешем в имени и обязательная перепроверка HTML.

Автоматическая связка «пуш → сайт» есть, и живёт она на самом сервере, а не
в GitHub: см. «Связка репозитория с сервером» ниже. До 11 августа 2026 её не
было — выкладку делали руками.

Как это проверить в любой момент, не заходя на сервер:

```bash
curl -sI https://arisheniaa.ru/ | grep -i last-modified
```

Метка одна на все файлы сайта и означает время последней выкладки, а не
правки конкретного файла.

## Репозиторий — источник правды, и это нужно удерживать

11 августа 2026 обнаружилось, что сайт **обогнал репозиторий**: на нём жила
работа, которой в гите не было ни в одной ветке — `canonical` и карточки
Open Graph на обеих страницах, `public/og.jpg`, `robots.txt`, `sitemap.xml`.
Значит выкладку собирали из рабочей копии с незакоммиченными правками, и
сборка из чистого клона дала бы сайт БЕДНЕЕ того, что стоит.

Расхождение устранено: всё живое возвращено в репозиторий и сверено
побайтово. Чтобы оно не возникло снова — правьте только в репозитории и
выкладывайте только собранное из него.

Сверка занимает секунду и врать не умеет: имена файлов в `dist/assets/` —
это хеши содержимого. Совпали с теми, что на сайте, — значит код совпал.

```bash
curl -s https://arisheniaa.ru/ | grep -oE 'assets/[A-Za-z]+-[A-Za-z0-9_-]+\.(js|css)'
```

Сравните вывод с `ls .design/hybrid/dist/assets/`. Разошлось — сайт собран
не из того, что лежит в `master`.

## Связка репозитория с сервером

Пуш в `master` доезжает до сайта сам, обычно за пять минут. Работает это на
сервере.

`/opt/arisheniaa-site/autodeploy.sh` — сторож. Таймер
`arisheniaa-autodeploy.timer` будит его каждые 5 минут; сторож спрашивает у
GitHub хеш последнего коммита и, если тот совпадает с уже собранным, молча
выходит. Разошлись — запускает `build.sh`.

Опрос, а не вебхук: вебхук отдаёт обновление мгновенно, но требует открытого
наружу обработчика, общего секрета и правки edge-прокси. Опрос не требует
ничего — сервер ничего не открывает наружу и не заводит ключей на стороне
GitHub. Задержка до пяти минут для сайта фотографа роли не играет.

Тяжёлая часть (`npm ci` и сборка в контейнере) выполняется только когда есть
что собирать. На хосте 3.8 ГБ памяти, разделённых с другими проектами;
гонять полную сборку каждые пять минут вхолостую нельзя.

### Когда сторож намеренно ничего не делает

Если в клоне есть незакоммиченные правки или коммиты, которых нет на GitHub,
сторож не собирает ничего и пишет об этом в журнал. Та же осторожность, что
и в `build.sh`, и она уже пригодилась: 11 августа 2026 на сервере лежали два
коммита с правками видимости, которых не было в репозитории, — молчаливая
перемотка откатила бы и их, и сайт.

Обратная сторона: пока расхождение не снято, сайт не обновляется вовсе, а
снаружи это выглядит как «пуши уходят, ничего не происходит». Смотреть надо
сюда:

```bash
journalctl -u arisheniaa-autodeploy.service -n 20 --output cat
```

Снять расхождение — но только убедившись, что серверные коммиты уже
перенесены в репозиторий:

```bash
cd /opt/arisheniaa-site/repo && git reset --hard origin/master
```

### Что где лежит на сервере

| путь | что это |
|---|---|
| `/opt/arisheniaa-site/repo` | клон репозитория, из него идёт сборка |
| `/opt/arisheniaa-site/build.sh` | сборка в контейнере `node:22` и публикация |
| `/opt/arisheniaa-site/autodeploy.sh` | сторож новых коммитов |
| `/opt/arisheniaa-site/site` | собранный сайт, его отдаёт Caddy |
| `/opt/arisheniaa-site/Caddyfile` | заголовки и кеширование, `root * /srv/site` |
| `/etc/systemd/system/arisheniaa-autodeploy.*` | служба и таймер |

Каталог `site` отдан контейнеру bind-монтом, поэтому `build.sh` синхронизирует
его СОДЕРЖИМОЕ через `rsync --delete`, а не подменяет каталог целиком: монт
привязан к inode, и подмена рвала его — сайт отдавал сплошной 404 при внешне
успешной сборке.

### Проверить, что связка жива

```bash
systemctl list-timers arisheniaa-autodeploy.timer
```

### Откуда взять эти файлы заново

Канонические копии лежат в репозитории, в `deploy/` — именно потому, что вся
эта история случилась из-за работы, которая жила только на сервере. Если
сторож придётся ставить заново:

```bash
install -m 755 deploy/autodeploy.sh /opt/arisheniaa-site/autodeploy.sh
install -m 644 deploy/arisheniaa-autodeploy.service /etc/systemd/system/
install -m 644 deploy/arisheniaa-autodeploy.timer /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now arisheniaa-autodeploy.timer
```

`build.sh` и `Caddyfile` в репозиторий НЕ перенесены: они старше и живут
своей жизнью на сервере вместе с `docker-compose.yml`. Захотите привести и их
к одному источнику — переносите целиком, а не по частям.

### Конвейер GitHub

`.github/workflows/build-check.yml` ничего не выкладывает — иначе он и сторож
спорили бы за один каталог на сервере. Он остался проверкой сборки: на
каждый пуш собирает сайт на чистой машине и убеждается, что в собранном CSS
есть утилиты Tailwind и правило стопки, а в `dist/` — обе страницы,
`robots.txt`, `sitemap.xml`, `og.jpg` и файл подтверждения Яндекса. Красный
крест там означает, что до сервера доезжать нечему.

## Куда выкладывать

Подойдёт любой из: Netlify, Vercel, Cloudflare Pages, GitHub Pages,
обычный сервер с nginx. Настройки для всех одинаковые:

| параметр | значение |
|---|---|
| команда сборки | `npm run build --prefix .design/hybrid` |
| папка публикации | `.design/hybrid/dist` |
| версия Node | 20 или новее |

Отдельных правил перенаправления не нужно: обе страницы (`index.html` и
`storyboard.html`) — настоящие файлы, а не маршруты одностраничного
приложения.

## ⚠️ Про GitHub Pages отдельно

Сайт ссылается на свои файлы АБСОЛЮТНЫМИ путями — `/services/…`,
`/storyboard/manifest.json`. Это верно, когда сайт лежит в корне домена:

- `arisheniaa.ru` — работает;
- `имя.github.io` (персональный сайт GitHub) — работает;
- `имя.github.io/название-репозитория/` (сайт проекта) — **НЕ работает**:
  браузер пойдёт за картинками в корень `имя.github.io`, а их там нет.
  Страница откроется без единой фотографии.

Если выкладывать на GitHub Pages именно проектом, нужно сначала задать
базовый путь в `.design/hybrid/vite.config.mts`:

```js
export default defineConfig({
  base: '/название-репозитория/',
  // …остальное без изменений
});
```

и пересобрать. На Netlify, Vercel, Cloudflare и своём домене этого не нужно.

## Что попадёт в публичный репозиторий

Если репозиторий делать открытым, вместе с кодом станут видны:

- все фотографии сайта и весь архив кадров раскадровки (254 снимка);
- цены, контакты и весь текст;
- **локальные пути к вашему архиву на компьютере** — в 18 файлах, включая
  `.design/storyboard-manifest.json`, лежат строки вида
  `C:\Users\Аришения\OneDrive\Рабочий стол\исходники\…`. Это раскрывает имя
  пользователя вашего компьютера и устройство ваших папок. Сами
  фотографии по этим путям недоступны, но информация лишняя.

Первые два пункта — это и есть содержимое сайта, они и так будут публичны.
Третий — нет: он нужен только для пересборки архива на вашей машине.

Убрать его можно, добавив в `.gitignore` строку
`.design/storyboard-manifest.json` и удалив файл из индекса:

```bash
git rm --cached .design/storyboard-manifest.json
```

Сайт от этого не сломается: собранный манифест
(`.design/hybrid/public/storyboard/manifest.json`, тот, что уходит в
браузер) локальных путей не содержит вовсе — проверено. Пересобрать
исходный манифест можно в любой момент:

```bash
node .design/scripts/storyboard-manifest.mjs
```

Но учтите: пересборка требует папку `исходники` на диске, поэтому на чужой
машине из чистого клона архив раскадровки заново не собрать. Готовые
превью в `public/storyboard/` в репозитории есть, и сайту их достаточно.
