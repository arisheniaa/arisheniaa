# Конфигурация сервера — копии того, что реально работает

Здесь лежат **копии** файлов из `/opt/arisheniaa-site/` и двух systemd-юнитов
с боевого сервера. Сняты с работающей машины, не написаны по памяти.

Заведены потому, что до сих пор эта часть сайта нигде не хранилась: код был в
гите, а то, чем он отдаётся наружу и как пересобирается, — только на сервере.
Погиб бы сервер — восстанавливать пришлось бы по памяти и по `DEPLOY.md`.

## Что здесь

| файл | что делает |
|---|---|
| `Caddyfile` | заголовки безопасности, кеширование, отдача статики на `:8080` |
| `docker-compose.yml` | контейнер сайта: лимит памяти, харденинг, сеть `edge` |
| `autodeploy.sh` | сторож: раз в 5 минут сверяет хеш с GitHub и зовёт сборку |
| `build.sh` | сборка в одноразовом контейнере node:22, без node на хосте |
| `smoke.sh` | проверка, что выложенный сайт отвечает и отдаёт то, что нужно |
| `seocheck.sh` | проверка мета-полей выложенных страниц |
| `systemd/*.service`, `systemd/*.timer` | запуск сторожа по расписанию |

## Главное правило: сервер — источник правды, здесь копии

Правка в этой папке **сама по себе ничего не меняет**. Файлы не выкладываются
автоматически: их правят на сервере руками и потом обновляют копию здесь.

Порядок такой:
1. правите на сервере, в `/opt/arisheniaa-site/`;
2. перезапускаете, что нужно (`docker compose up -d` или `systemctl daemon-reload`);
3. убеждаетесь, что сайт жив (`./smoke.sh`);
4. только теперь копируете файл сюда и коммитите.

Обратный порядок (сначала коммит, потом сервер) выглядит аккуратнее, но
оставляет окно, в котором репозиторий обещает одно, а сайт работает по-другому.

## Проверить, не разошлись ли копии с сервером

```bash
for f in Caddyfile docker-compose.yml autodeploy.sh build.sh smoke.sh seocheck.sh; do
  ssh root@194.87.187.207 "cat /opt/arisheniaa-site/$f" | diff -q - "server/$f" > /dev/null \
    && echo "$f — совпадает" || echo "$f — РАЗОШЛОСЬ"
done
```

## Чего здесь нет и почему

**`edge-caddy`** — общий привратник на портах 80 и 443, он раздаёт запросы по
доменам между тремя сайтами (`arisheniaa.ru`, `uklonskiyk.ru`,
`elegia-tula.ru`). Он не принадлежит этому сайту, живёт в `/opt/edge-caddy/` и
в этот репозиторий не кладётся: чужие домены в личном портфолио ни к чему, а
разделение контуров — прямое требование владелицы.

## Находка при снятии копий: указания про Pinterest в `DEPLOY.md` устарели

В `DEPLOY.md` есть раздел с готовой строкой CSP, разрешающей домены Pinterest.
Он писался, когда на странице «Придумать съёмку» стояли доски Pinterest, и их
резал наш собственный заголовок безопасности.

**Досок больше нет** — их убрала сама владелица (Ф64: «убери доски Pinterest и
любые упоминания его в тексте»). В действующем `Caddyfile` доменов Pinterest
тоже нет, и это правильно: разрешать чужим скриптам исполняться на сайте ради
блока, которого не существует, — ослаблять защиту без всякой пользы.

Раздел в `DEPLOY.md` помечен историческим. Если доски когда-нибудь вернутся,
строка там готова, и тогда её надо будет применить.
