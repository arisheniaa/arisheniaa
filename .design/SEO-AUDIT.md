# Аудит поисковой видимости

Замерено 11 августа 2026 на живом сайте `https://arisheniaa.ru`, сборка
`d4ca150`. Ничего по итогам аудита не менялось — это снимок состояния и
список предложений, решение за владельцем.

Как перемерить всё то же самое — в конце файла.

## Что уже сделано хорошо

Технически сайт здоров, и это не формальность: большая часть находок ниже
про содержание, а не про устройство.

| | значение |
|---|---|
| заголовок вкладки | 58 символов, с ключевыми словами и городами |
| описание | 134 символа, с ценами |
| `canonical` | есть на обеих страницах, адреса разные |
| Open Graph + `twitter:card` | есть, с картинкой 1200×630 |
| `lang="ru"` | есть |
| `robots.txt`, `sitemap.xml` | есть, права в обеих консолях подтверждены |
| зеркала | `http://` и `www.` отвечают 308/301 на основной адрес |
| первый байт | 75 мс |
| сжатие | gzip включён |
| кеширование | ассеты с хешем — вечный кеш, HTML — перепроверка |
| цены в тексте | 8 значений, от 3 000 до 8 000 ₽ |

## Критично

### 1. Роботу без JavaScript сайт пуст

Весь HTML, который отдаёт сервер:

```html
<body><div id="root"></div></body>
```

6116 байт, из них содержимого — ноль. Ни заголовка, ни текста, ни цен: всё
рисует React после загрузки бандла.

Кого это задевает, по убыванию:

- **Сборщики ИИ** (GPTBot, ClaudeBot, PerplexityBot и подобные) как правило
  не выполняют JavaScript вовсе. Для ответов нейросетей сайт сейчас —
  пустая страница. Ровно та задача, ради которой аудит и затевался.
- **Яндекс** JS выполняет заметно хуже Google и не на всех страницах.
- **Google** выполняет, но во вторую очередь: сначала индексируется голый
  HTML, отрисовка ставится в очередь и может занять от часов до недель.

Лечится пререндером: при сборке страницу открывают в браузере, дожидаются
отрисовки и сохраняют получившийся HTML в файл. `playwright` уже стоит в
зависимостях проекта и уже используется для снимков — новых зависимостей не
нужно.

Риск, который надо проверить на живой странице: React 19 должен подхватить
готовую разметку без расхождений. Если расхождение будет, оно проявится
дёрганием анимаций в момент загрузки.

### 2. Разметки Schema.org нет ни строчки

`application/ld+json` не встречается ни в HTML, ни в исходниках. Для
локального бизнеса с прайсом и географией это самая дешёвая из
неиспользованных возможностей.

Что стоило бы описать: `ProfessionalService` или `LocalBusiness` — имя,
адрес сайта, картинка, `areaServed` с Москвой и Тулой, `priceRange`,
`sameAs` на телеграм и инстаграм; каталог услуг с четырьмя жанрами съёмки и
их ценами; `Person` как автора.

Отдельно важно: разметка лежит в HTML статически, поэтому **работает даже
без выполнения JS**. То есть частично закрывает пункт 1 для ИИ — они
структурированные данные читают охотно.

## Серьёзно

### 3. В заголовках нет ни одного поискового запроса

| уровень | сейчас |
|---|---|
| H1 | Создаю ваше кино |
| H2 | Кто снимает · Как получается кино · Что можно у меня снять · С чего начать и как это всё устроено |
| H3 | Индивидуальная · Парная · Творческая · Плёночная |

На голосе и красиво, но поиску не сообщает ничего. Обиднее всего H3: до
«Индивидуальной фотосессии» не хватает одного слова, и это правка на минуту,
которая ничего не ломает в дизайне.

### 4. Ключевых слов нет в тексте

Подсчёт по всему DOM отрисованной главной (2567 символов):

| слово | вхождений |
|---|---|
| фотосессия | **0** |
| портрет, портретная | **0** |
| фотосъёмка | **0** |
| студия | **0** |
| ретушь | **0** |
| фотограф | 5 |
| Москва | 4 |
| Тула | 4 |
| плёнка | 4 |

«Портретный фотограф» стоит в заголовке вкладки, но слова «портрет» на самой
странице нет ни разу. «Фотосессия» — самое частотное коммерческое слово в
нише — не встречается вовсе.

### 5. Текста мало

2567 символов на главной, 411 на «Придумать съёмку». Вторая страница —
интерактивный квиз, её содержимое рождается по ходу ответов, и для поиска
она почти пуста.

### 6. У 11 картинок из 25 нет `alt`

Для фотографа это не мелочь: поиск по картинкам в этой нише — работающий
источник обращений. Заодно `alt` — единственное, что о фотографии узнают
поисковик и незрячий посетитель.

### 7. Два города на одной странице

«Фотограф Москва» и «фотограф Тула» — разные запросы с разной выдачей. Одна
страница не может быть сильной в обоих: она размывает оба.

## Помельче

- H2 на «Придумать съёмку» — «Соберем для вас референсы к вашей съемке» —
  без «ё», тогда как весь остальной сайт «ё» соблюдает.
- Нет блока вопросов и ответов. Это и текст с запросами, и разметка
  `FAQPage`, и материал, который охотно цитируют ИИ.
- В карте сайта нет картинок. Для фотографа отдельная карта изображений —
  дешёвый способ ускорить их попадание в поиск.
- Нет `llms.txt` — складывающегося соглашения о том, как объяснить
  нейросетям, что за сайт и что на нём есть.

## Предложения, по отдаче на усилие

| # | правка | эффект | сложность | ломает дизайн |
|---|---|---|---|---|
| 1 | Schema.org с ценами и городами | высокий, в т.ч. ИИ | низкая | нет |
| 2 | `alt` для 11 картинок | средний | низкая | нет |
| 3 | Ключевые слова в заголовки разделов | высокий | низкая | нет |
| 4 | Пререндер HTML при сборке | **решает пункт 1** | средняя | нет, но требует проверки |
| 5 | Расширить тексты до 5–7 тыс. знаков | высокий | средняя | нужен голос владельца |
| 6 | Страницы под города | высокий на локальных | высокая | новая структура |
| 7 | `llms.txt` и карта картинок | небольшой | низкая | нет |

Пункты 1–3 и 7 безопасны: не трогают ни вёрстку, ни тексты, ни голос.
Пункт 5 без владельца делать нельзя — это его голос. Пункт 6 меняет
структуру сайта и требует отдельного решения.

## Как перемерить

Что отдаётся роботу без JS:

```bash
curl -s https://arisheniaa.ru/ | sed -n '/<body>/,/<\/body>/p'
```

Есть ли структурированные данные:

```bash
curl -s https://arisheniaa.ru/ | grep -c "application/ld+json"
```

Заголовки, картинки без `alt` и объём текста — в консоли браузера на
открытой странице:

```js
[...document.querySelectorAll('h1,h2,h3')].map(h => h.tagName + ': ' + h.innerText)
[...document.querySelectorAll('img')].filter(i => !(i.getAttribute('alt')||'').trim()).length
document.body.textContent.replace(/\s+/g,' ').length
```
